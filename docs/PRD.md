# 钓鱼地图与记录小程序 PRD v1.2（武汉试点）

> 状态：首版范围已收敛，可进入里程碑开发  
> 日期：2026-08-04  
> 首发形态：微信小程序  
> 初次试点城市：武汉  
> 首要钓法：台钓  
> 项目代号：Play Holiday（正式产品名待定）

### 0.1 P0 场景边界

P0 以**武汉城市湖库及郊区合法野钓的台钓出钓决策**作为初次试点。武汉用于完成存量地点铺底、用户追加更新和运营闭环验证，不代表产品长期只服务武汉。首轮验证排除长江、汉江干流、水产种质资源保护区和饮用水一级保护区，也不把收费黑坑作为首轮核心供给。收费钓场与钓具店可以作为地图 POI 展示，但黑坑放鱼日历、商家认领与经营工具进入 P1 单独验证。

## 1. 产品摘要

### 1.1 一句话定位

> **本地出钓决策助手**——用自己的出钓记录形成私人规律，用钓友匿名趟次形成武汉水域级鲜活状态；精准钓位默认不进入公共池。

### 1.2 核心问题

武汉台钓用户出发前真正需要回答的不是“网上有没有钓点”，而是：

- 今天是否适合出钓；
- 哪片水域近期有人去、是否有口；
- 当前是否允许垂钓，是否存在走水、水位、道路或管理风险；
- 过去在相似天气、时间和钓法下，自己在哪些地方表现更好。

现有通用钓鱼产品覆盖地图、天气、识鱼、渔获和社区，但公开钓点常见过期、来源不明、精准点泄露和只展示正向渔获的问题。首版不追求全国钓点数量，而追求武汉少量水域的近期趟次覆盖、来源透明和位置保护。

### 1.3 产品结构

产品由两个互相促进、但可独立成立的价值层组成：

1. **私人价值层：** 天气参考、识鱼、出钓日志、私人标点和个人复盘。没有社区数据也可使用。
2. **公共聚合层：** 用户自愿贡献脱敏后的水域级趟次，形成近期有口、空军和现场状态。

地图直接进入 P0，作为两层数据的主要入口与决策界面。

## 2. 目标与非目标

### 2.1 P0 目标

1. 用户首次打开后 60 秒内能看到武汉附近可参考的水域、钓场或钓具店，以及今日出钓参考。
2. 用户能在约 10 秒内记录一次“空军／有口／爆护”趟次。
3. 用户可以保存精准私人标点，但默认不把精准坐标上传到公共数据链路。
4. 公共地图能诚实展示水域级近期状态、数据来源和最后确认时间。
5. 在 30 天内验证水域级情报是否改变真实出钓决策，以及用户是否愿意持续贡献匿名趟次。

### 2.2 P0 非目标

- P0 不同时铺开全国地图和全国内容社区；武汉试点成立后再按城市复制；
- 不承诺“使用后一定上鱼”；
- 不做陌生人之间的精准钓点交易或互换；
- 不做短视频流、私聊、群聊、直播和排行榜；
- 不做商城、二手交易、钓场预约和会员；
- 不建设完整商家后台和复杂风控系统；
- 不把小红书内容未经授权搬入产品。

## 3. 目标用户

### 3.1 首要用户

武汉本地、每月至少出钓 1–2 次的台钓用户，主要前往规则清晰的城市湖库或郊区合法野钓水域。他们已经会使用微信，愿意看地图和天气，但不愿公开自己的精准野钓位置。

### 3.2 次要用户

- 刚开始台钓、需要找可去水域和学习记录的新手；
- 愿意帮助核实水域状态的本地资深钓友；
- 收费钓场和钓具店经营者；
- 提供本地攻略、但要求保护具体位置的创作者。

### 3.3 暂不重点服务

- 以海钓或船钓为主的用户；
- 以路亚为唯一钓法的用户；
- 只看泛娱乐内容、没有真实出钓意图的用户；
- 以销售或交易天然水域渔获为目的的用户。

## 4. 武汉本地产品约束

### 4.1 水域规则

首版地图必须把“允许参考”“条件性允许”“禁止垂钓”“信息待核实”分开展示，不得把“禁捕”机械等同于“完全禁钓”。

目前应纳入规则库的最低事实包括：

- 长江、汉江武汉段处于十年禁捕期，允许的休闲垂钓受钓具、钓法和渔获交易等规则约束；
- 武汉相关水产种质资源保护区严禁垂钓；
- 长江、汉江桥梁上禁止垂钓；
- 饮用水水源一级保护区禁止垂钓；
- 各区仍可按生态、行洪、饮水、人身安全等因素划定禁钓区或禁钓期。

产品中的规则提示只用于帮助用户查阅，不替代现场公告和主管部门要求。每条状态必须保存发布机关、来源链接、适用范围、发布日期、有效期和最近复核时间。

水域是否允许垂钓与具体钓法、线组和装备是否合规是两个独立维度。规则库和水域详情至少要能表达：

- 允许杆数、每线允许钩数和单钩／多钩限制；
- 禁用饵料、活体水生生物饵料、探鱼设备、船筏或桥梁垂钓等限制；
- 限制适用的水域、时间、主管机关、原文链接和最近复核日期；
- “水域可参考，但当前钓法不适用”的单独状态，禁止用一个“可钓”标签覆盖全部条件。

首轮运营水域不得位于长江、汉江干流或相关水产种质资源保护区。后续若展示这些区域，规则与风险提示优先于鱼情和热度；禁止或高风险状态不展示诱导出钓的公开热度。

### 4.2 本地竞争变量

武汉已有政企民联动的“汉钓通”，公开信息显示其包含电子钓点导航、禁钓预警和渔获登记。因此本产品不能把“武汉钓点导航”本身当差异化，必须重点验证：

- 私人历史规律是否比通用登记更有复用价值；
- 空军也计入的匿名趟次是否能产生更诚实的新鲜度；
- 位置保护能否换来用户持续记录；
- 水域级近期有口和现场状态是否能改变决策。

### 4.3 地图实施原则

地图进入 P0，但按数据类型分层：

1. **地图服务商已有 POI：** 钓具店、收费钓场、公共设施等，保留来源和更新时间。
2. **运营核实水域：** 由运营建立水域卡和粗粒度地图入口，状态须带来源。
3. **用户私人标点：** 精准位置默认仅自己可见，优先保存在本地。
4. **公共趟次：** 只关联已存在的水域 ID 或粗粒度区域，不公开原始精准点。
5. **新增公共水域申请：** 进入人工审核，审核通过后生成公共水域卡；不允许提交后即时公开。

使用持牌地图 SDK 不等于平台所有新增内容自动合规。产品必须保留新增内容审核、纠错、下线、来源追踪和审计能力。

## 5. 信息架构

底部导航采用四栏：

1. **首页**：今日出钓参考、附近水域状态、快速继续上次记录。
2. **地图**：水域、收费钓场、钓具店、禁钓或危险状态、私人标点。
3. **记录**：一键趟次、拍照识鱼、详细渔获日志。
4. **我的**：私人日志、收藏、私人标点、个人规律、设置与数据管理。

不设置独立“社区”Tab。公共信息围绕水域详情和地图展开。

## 6. 核心用户流程

### 6.1 找地方并做出钓决策

1. 用户允许城市级定位或手动选择武汉区域。
2. 首页展示今日及未来 3 天逐时天气参考。
3. 用户进入地图，查看附近水域、钓场和钓具店。
4. 用户按距离、类型、近期状态和是否已收藏筛选。
5. 用户打开水域卡，查看近 7 天趟次、有口占比、最近有口、现场状态、来源和更新时间。
6. 用户收藏、导航、放弃、改期或换水域。
7. 产品记录决策动作，用于判断情报是否真正有用。

### 6.2 一键记录趟次

1. 用户点击“我在这钓”。
2. 系统在客户端判断附近候选水域，用户确认关联水域。
3. 用户选择空军／有口／爆护之一。
4. 可选补充可钓、有人管理、走水、水位异常、道路危险。
5. 用户选择“只存私人记录”或“匿名贡献到该水域”；默认展示清晰的水域级贡献说明。
6. 弱网时本地排队，恢复网络后提示用户同步。

### 6.3 拍照识鱼并形成日志

1. 用户拍照或选择图片。
2. 系统返回 1–3 个候选鱼种和置信提示。
3. 用户人工确认或选择“不确定”。
4. 系统自动补充时间和天气；位置遵循私人位置设置。
5. 重量、长度、钓法、饵料和备注均为可选。
6. 保存到私人日志，并可选择是否匿名贡献鱼种和趟次结果。

### 6.4 新增私人点或申请公共水域

- 新增私人点：用户长按地图或使用当前位置，输入自定义名称，只在私人层显示。
- 申请公共水域：用户选择粗粒度区域、填写公开名称和证据来源，进入审核队列；审核前仅申请人可见。
- 不提供“一键把私人精准点公开给所有人”。

## 7. P0 功能需求与验收标准

### 7.1 首页与出钓参考

功能：

- 武汉天气、气压、风向风力、降水概率和逐时变化；
- 今日／未来 3 天出钓窗口；
- 最近查看和收藏的水域；
- 附近近期有趟次的水域；
- 明示“天气参考不代表渔获保证”。

验收：

- 无定位权限时可手动选择武汉行政区；
- API 异常时显示数据更新时间和降级状态，不展示过期数据为实时数据；
- 用户可查看推荐依据，不输出无法解释的“必中指数”。

### 7.2 地图

功能：

- 腾讯位置服务／微信地图组件承载底图；
- 水域、收费钓场、钓具店、私人点和规则状态图层；
- 聚合点、视野内搜索、回到当前位置；
- 筛选：水域／钓场／钓具店、近 7 天有更新、已收藏、规则状态；
- 列表与地图双视图；
- 导航调用地图服务商能力。

验收：

- 不同来源使用清晰图例，商家自述不得显示为用户核实；
- 禁止、条件性允许、待核实在颜色和文案上可区分；
- 用户私人点不会出现在其他账号或公共接口；
- 公共水域必须有 `source_type`、`checked_at` 和可下线状态；
- 用户新增公共水域未经审核不得公开。

### 7.3 水域详情

功能：

- 水域名称、所属区域、距离、导航入口；
- 近 7 天有效趟次数和有口趟次占比；
- 最近一次有口时间；
- 主要鱼种和主要钓法；
- 可钓／禁钓／走水／水位／道路等状态；
- 信息来源、最近确认时间和纠错入口；
- 收藏和匿名贡献入口。

验收：

- 少于最低样本量时不展示百分比，只显示实际趟次数和“样本不足”；
- “近期无人贡献”和“近期有人但空军”必须分开；
- 禁钓或安全信息没有来源时只能显示“用户报告，待核实”，不能直接变为平台结论；
- 规则冲突时显示更谨慎状态并进入运营复核。

### 7.4 趟次与私人日志

功能：

- 空军／有口／爆护三选一；
- 可选现场状态、照片和详细渔获；
- 离线保存、同步重试、编辑和删除；
- 私人／匿名水域级两种用途；
- 历史列表和基础筛选。

验收：

- 主流程在正常网络下 10 秒左右可完成；
- 详细字段不阻塞主流程；
- 用户删除私人日志时同步删除对应云端私人数据；已进入匿名聚合的数据按隐私说明和适用规则处理；
- 上传前明确展示公共贡献不会包含精准钓位。

### 7.5 拍照识鱼

功能：

- 相册／相机输入；
- 候选鱼种、相似度提示和人工确认；
- 识别失败可继续保存为“不确定鱼种”；
- 识别结果进入日志编辑页。

验收：

- 不把低置信结果包装成确定结论；
- 用户可纠正结果；
- 识别服务失败不影响保存照片和趟次；
- 对外分享图片前清除 EXIF。

### 7.6 收藏、分享和个人复盘

功能：

- 收藏水域／钓场／钓具店；
- 今日出钓窗口或水域状态工具卡；
- 查看个人在时间、天气、钓法和水域维度的基础历史统计。

验收：

- 分享卡不包含私人精准位置；
- 分享落地页直接进入对应水域或当天出钓参考，不进入泛首页；
- 样本不足时不生成“最佳规律”结论。

### 7.7 运营审核最小能力

P0 不开发完整后台，先使用受控表格或最小管理页面：

- 水域、POI、规则来源的新增、编辑、隐藏和下线；
- 公共水域申请审核；
- 用户纠错和危险报告处理；
- 内容来源、处理人和处理时间留痕；
- 敏感水域紧急全量隐藏开关。

验收：

- 高风险规则纠错可以在 4 小时内处理或先隐藏；
- 普通 POI 纠错在 2 个工作日内处理；
- 所有公开坐标和规则状态可追溯到来源或审核记录。

## 8. 数据与隐私设计

### 8.1 核心数据实体

`WaterBody` 水域：

- `id`, `name`, `district`, `coarse_location`, `source_type`；
- `public_status`, `checked_at`, `source_url`, `effective_from`, `effective_to`；
- `visibility`, `review_status`, `risk_level`。

`Trip` 趟次：

- `id`, `user_id`, `water_body_id`, `result`；
- `started_at`, `weather_snapshot`, `method`；
- `site_status[]`, `visibility`, `created_at`, `deleted_at`。

`PrivateSpot` 私人点：

- 默认使用客户端本地 ID、名称、加密坐标和备注；
- 只有用户主动开启云同步时才创建服务端加密副本。

`Catch` 渔获：

- `trip_id`, `species_candidate`, `species_confirmed`；
- `weight`, `length`, `bait`, `photo_ref`，均允许为空。

`Place` 商业或公共 POI：

- `provider_id`, `type`, `name`, `provider_location`；
- `claim_source`, `verified_status`, `checked_at`。

`RuleSource` 规则来源：

- `authority`, `title`, `url`, `published_at`；
- `effective_from`, `effective_to`, `scope`, `last_checked_at`。

`FishingConstraint` 钓法与装备约束：

- `id`, `water_body_id`, `rule_source_id`, `method_scope`；
- `rod_limit`, `hooks_per_line_limit`, `bait_restrictions[]`, `equipment_restrictions[]`；
- `effective_from`, `effective_to`, `checked_at`, `display_level`。

### 8.2 位置处理

- 浏览附近信息时只请求必要定位权限；拒绝定位仍可手选区域。
- 用户创建的私人精准点和单次站位默认本地保存，与公开地点实体分开处理。
- 收费钓场、公开湖泊入口、停车点等地点实体可按来源规则公开，但不因此公开用户的个人站位。
- 公共趟次在客户端映射为水域 ID 或粗粒度区域后上传。
- 云端私人点必须单独开关、单独告知、可导出、可删除。
- 后台日志不得长期记录无必要的原始定位参数。
- 任何热力聚合必须设置最小样本量、时间延迟和敏感水域禁用策略。

### 8.3 内容与图片

- 公共图片清除 EXIF；
- 平台按微信生态要求进行内容安全检测；
- 原图与公开图分离存储，权限隔离；
- 举报、撤回和删除链路可用；
- 不使用小红书未授权图片、正文或用户信息填充地图。

## 9. 状态与可信度模型

P0 不展示复杂综合分数，只展示可解释标签：

- **运营核实**：运营根据权威来源或现场确认；
- **多人近期确认**：规定时间窗内多个不同用户贡献；
- **近期有趟次**：近 7 天有有效记录；
- **样本不足**：不足以计算比例；
- **用户报告待核实**：单个或低可信来源；
- **信息较旧**：超过设定时间窗；
- **存在争议**：来源冲突；
- **禁止或高风险**：有权威来源或运营紧急处理。

有效趟次需要满足：账号通过基本风控、时间合理、关联水域存在、没有明显重复或异常频率。P0 先人工抽查，不构建复杂信誉算法。

## 10. 冷启动方案

### 10.1 首批范围

- 武汉 2–3 个运营可核实、台钓用户真实会去的城市或郊区湖库；
- 每个水域 6–8 名每月至少出钓一次的种子钓友；
- 一批来自持牌地图服务商的钓具店和收费钓场 POI；
- 所有水域先完成基本规则来源核对。

首批水域不能只按知名度选择，应满足：

- 能确认当前是否允许垂钓；
- 不处于种质资源保护区或饮用水一级保护区；
- 不位于长江、汉江干流，且钓法与装备规则能够被结构化表达；
- 运营能在 30 天内触达真实台钓用户；
- 交通和现场安全信息可核实；
- 水域粒度足以保护具体钓位。

### 10.2 种子钓友任务

- 每周至少提交一次真实趟次，包括空军；
- 帮助验证一键记录是否足够轻；
- 反馈水域级展示是否过粗或泄露钓位；
- 对状态错误发起纠错；
- 不要求贡献精准野钓点。

奖励以身份、共创资格、线下活动和产品优先权为主。若只能靠逐条现金购买才能维持贡献，应视为供给模型的风险信号。

### 10.3 小红书使用边界

允许：

- 搜集公开需求和常见痛点；
- 发现武汉台钓创作者并邀请访谈；
- 经作者明确授权后，以署名和原文链接合作；
- 招募种子用户或投放验证内容。

不允许：

- 批量抓取笔记、图片、评论和用户资料；
- 把模糊描述人工反推成精准坐标后公开；
- 未经授权复制正文、图片或作者身份；
- 把内容平台热度伪装成产品内真实趟次。

## 11. 30 天验证计划

### 11.1 双轨执行

运营轨：人工制作和分发水域情报卡，招募种子用户，回收用户在看到情报前的出钓计划、看到后的真实决策与趟次。

产品轨：同步上线地图、私人日志、一键趟次、识鱼录入和水域卡的灰度版本。

### 11.2 主漏斗

> 记录看卡前计划 → 收到或看到水域级情报 → 查看详情／收藏／询问 → 48 小时内确认原计划、出钓、改期、取消或换水域 → 回流提交趟次结果

人工投喂实验只用于验证“水域级新鲜信息的需求上限”“信息能否影响真实决策”和“用户是否愿意贡献趟次”，不把运营持续供给误写成产品已形成自持数据飞轮。分析时按水域分别判断，并区分：

- 信息价值不足：有足够新鲜样本，但用户不查看或不改变决策；
- 密度不足：核心字段长期因样本不足而无法展示；
- 供给不足：用户消费信息，但不愿持续回流趟次。

### 11.3 阶段判断

第 14 天检查：

- 一键趟次是否仍有明显操作阻力；
- 用户是否理解私人点和匿名水域贡献的区别；
- 水域卡是否导致过“粒度太粗没用”或“粒度太细烧点”；
- 哪一步漏斗下降最严重。

第 30 天判断：

- **继续：** 出现重复使用，匿名趟次无需逐条现金刺激，且水域情报确实改变一部分真实决策；
- **调整：** 私人日志成立但公共贡献不足，转为私人复盘优先；或公共消费成立但供给不足，调整种子和激励机制；
- **停止该主线：** 用户既不复用私人记录，也不因水域级情报改变决策，且贡献只能靠持续付费购买。

小样本结果只用于业务判断，不宣称统计显著。

## 12. 指标与埋点

### 12.1 北极星指标对

- 供给：每周有可用趟次覆盖的核心水域数、核心水域 7 天新鲜覆盖率。
- 需求：消费水域情报后 48 小时内产生决策动作并回流趟次的用户数。

### 12.2 关键事件

- `home_view`, `forecast_detail_view`；
- `map_view`, `map_filter_apply`, `place_card_open`；
- `water_detail_view`, `water_save`, `navigation_start`；
- `trip_start`, `trip_result_select`, `trip_submit`, `trip_sync_success`；
- `fish_identify_start`, `fish_identify_result`, `fish_species_correct`；
- `privacy_choice_view`, `anonymous_contribution_submit`；
- `rule_source_view`, `place_correction_submit`；
- `share_card_generate`, `share_landing_open`；
- `private_spot_create`, `cloud_private_spot_enable`, `data_delete`。

### 12.3 诊断指标

- 首次日志完成率和第二次记录率；
- 一键趟次完成时长与完成率；
- 空军上报占比；
- 匿名贡献率和拒绝原因；
- 水域详情到收藏／导航转化；
- 情报导致改期、取消或换水域的比例；
- 每周新增有效趟次与过期趟次之比；
- 规则来源查看和纠错率；
- 举报、撤销、审核驳回和错误下线率；
- 分享带来的武汉本地有效新增和后续决策动作。

不把 DAU、总发帖数和精准点公开率作为首要成功标准。

## 13. 非功能需求

### 13.1 户外可用性

- 关键按钮适配单手、湿手和强光；
- 结果选择按钮具备大点击区域和高对比度；
- 弱网和无网时不丢记录；
- 字号和状态图标适合中老年用户；
- 定位失败、地图失败和天气失败均有可理解降级。

### 13.2 性能

- 首页首屏目标 2.5 秒内出现基本骨架和缓存信息；
- 地图移动采用视野内加载与聚合，避免一次加载全城点位；
- 图片上传前压缩，识鱼任务展示进度并可后台恢复；
- 趟次离线队列具备幂等 ID，避免重复提交。

### 13.3 安全与治理

- 最小权限请求，不在启动时一次索取所有权限；
- 私人位置与公共数据分库或至少分权限域；
- 运营账号使用最小权限和操作留痕；
- 敏感水域支持批量隐藏；
- 对假点、商家刷点、GPS 模拟、盗图和异常频率保留基础风控接口。

## 14. 技术实现建议

现有项目使用 Taro 4、React 18、TypeScript 和 Less，继续复用微信小程序路线。

建议的首版模块：

- 客户端：现有 Taro 工程；
- 地图：腾讯位置服务／微信地图组件；
- 天气：选择能提供武汉逐时天气并允许商业使用的数据源；
- 后端：轻量 Node.js API 或微信云开发，优先缩短验证周期；
- 数据库：水域、趟次、渔获、POI、规则来源和审核记录；
- 对象存储：原图和公开脱敏图分路径、分权限；
- 识鱼：复用现有 API，增加候选结果、失败降级和用户纠正；
- 运营：首期受控表格导入／导出加最小管理接口。

正式技术方案需单独输出，尤其要说明位置数据流、私人数据加密、公共聚合、地图新增内容审核和删除机制。

## 15. 版本计划

以小团队为基准的建议顺序，不作为固定工期承诺：

### 阶段 0：1 周

- 确认首批 2–3 个合法城市／郊区湖库，以及每水域 6–8 名种子用户；
- 建立规则来源表和地图数据字典；
- 建立钓法／线组／装备限制字段，并完成首批水域规则复核；
- 确定地图、天气和后端服务；
- 完成埋点方案与低保真流程。

### 阶段 1：2–3 周

- 首页天气参考；
- 地图和水域详情；
- 私人标点；
- 现有识鱼流程接入日志；
- 一键趟次与离线队列。

### 阶段 2：2 周

- 水域聚合卡；
- 匿名贡献和客户端脱敏；
- 收藏、导航、纠错和工具分享卡；
- 最小运营审核能力。

### 阶段 3：1–2 周

- 武汉种子用户灰度；
- 修复弱网、定位、地图和隐私理解问题；
- 第 14 天与第 30 天实验复盘；
- 决定扩大水域、调整定位或停止公共聚合主线。

## 16. P1 与 P2 路线

### P1：P0 证明复用与贡献后

- 收藏水域状态提醒；
- 更完整的个人规律和季节复盘；
- 指定好友的可撤销私人点分享；
- 商家认领与用户反馈分开展示；

- 更多武汉水域和钓法；

### P2：单城单位经济成立后

- 收费钓场预约和活动；
- 钓具店导购与优惠；
- 高级天气和历史分析会员；
- 本地赛事、俱乐部和约钓；
- 城市复制工具；
- 原生 App 与更强离线能力。

## 17. 上线检查清单

- [ ] 首批水域均有状态来源、复核时间和下线负责人；
- [ ] 种质资源保护区、饮用水一级保护区和桥梁禁钓规则已建立；
