# Codex 产品提案 v0.1

## 一、核心产品主张

钓鱼产品的第一价值不应是“看内容”，而应是帮用户做一次真实出钓决策：

> 今天什么时间、去附近哪里、可能钓到什么、现场是否仍然可钓。

产品不把“钓点数量”作为主要卖点，而把“近期是否有效、信息从何而来、何时更新”作为地图的核心信息。

## 二、核心差异化

### 1. 钓点新鲜度

每个地点展示：

- 最近一次有效确认时间
- 近 7 天真实渔获数量
- 最近一次出鱼时间
- 当前可钓、信息较旧、存在争议、禁钓或危险等状态
- 状态信息的来源类型

### 2. 可信度

可信度综合以下信号：

- 是否在地点附近提交
- 是否包含现场照片
- 是否有多个不同用户确认
- 信息更新时间
- 提交者历史贡献质量
- 是否经过商家、创作者或运营核实

用户侧不展示复杂分数，只展示“近期有效”“多人确认”“信息较旧”等可理解标签。

### 3. 标点隐私

发布渔获和添加地点时提供：

1. 精准位置，仅自己可见
2. 约一公里模糊范围
3. 只显示水域名称
4. 完全公开

野钓内容默认选择模糊范围或水域名称。分享海报不包含精准坐标，并清除图片 EXIF 位置信息。

## 三、首次价值设计

即使社区数据很少，新用户首次进入仍能获得：

- 当前城市天气和参考出钓时段
- 已人工核实的基础钓点、收费钓场和钓具店
- 收藏、导航和私人标点工具
- 拍照识鱼
- 个人渔获日志

产品早期不伪造热度或鱼获。数据不足时明确显示“暂无近期渔获”或“信息等待核实”。

## 四、核心用户流程

### 流程 A：寻找出钓地点

1. 用户查看今日出钓建议
2. 进入附近地图
3. 按距离、鱼种、钓法和更新时间筛选
4. 查看地点详情和近期状态
5. 收藏或导航

### 流程 B：完成渔获记录

1. 上传照片
2. AI 返回候选鱼种
3. 用户人工确认
4. 自动补充时间、天气和气压
5. 用户选择水域与位置范围
6. 补充重量、长度、钓法和饵料
7. 发布并生成分享战报

### 流程 C：更新地点状态

1. 用户在地点附近进入详情
2. 选择“更新现场情况”
3. 提交可钓、禁钓、水位、走水、封路或危险信息
4. 系统根据位置、图片和其他用户确认更新状态

## 五、MVP 功能优先级

### P0：必须存在

- 城市选择与定位
- 基础天气与参考出钓时段
- 地图、地点聚合和基础筛选
- 钓点详情
- 收藏和导航
- 拍照识鱼及人工确认
- 渔获发布
- 位置隐私控制
- 钓点纠错与现场状态更新
- 微信分享战报
- 运营审核能力

### P1：验证留存后加入

- 收藏钓点状态提醒
- 周末出钓提醒
- 私人精准标点
- 个人渔获统计和鱼种图鉴
- 本地贡献者身份
- 商家认领和认证
- 关注水域

### P2：验证商业价值后加入

- 收费钓场预约
- 钓具店优惠和商品导购
- 高级天气与历史分析会员
- 本地赛事、俱乐部和约钓
- 城市复制工具

## 六、冷启动策略

### 城市聚焦

只选择一个能够线下触达钓友、钓具店和钓场的城市，优先保证地图新鲜度，不追求全国覆盖。

### 数据分层

- 基础层：水域、商家、收费钓场、公共设施
- 核实层：运营或合作钓友确认的信息
- 动态层：近期渔获、现场状态和用户纠错
- 私人层：用户自己的精准标点和日志

### 种子用户机制

招募本地钓友成为“城市共建者”，核心任务不是发普通帖子，而是确认地点状态、提交真实渔获和纠正过期信息。

### 内容平台合作

从小红书等平台发现活跃作者，取得授权后将攻略整理成结构化地点卡片，保留作者署名和原内容入口。

## 七、增长设计

优先发展三类分享：

- 工具型：今日鱼情、周末出钓窗口、潮汐和天气摘要
- 成就型：渔获战报、个人最佳、鱼种图鉴
- 利他型：禁钓提醒、水位变化、近期出鱼、道路和安全信息

分享落地页不进入泛首页，而进入与分享内容相关的水域、鱼种或城市页面。

## 八、衡量指标

北极星指标：每周新增的有效“钓点—渔获”关联记录数。

辅助指标：

- 新用户首次查看有效地点详情的比例
- 地点详情到收藏或导航的转化率
- 导航用户在 48 小时内记录渔获的比例
- 每周有新状态的地点占比
- 渔获发布完成率
- 分享带来的新用户数
- 7 日和 30 日留存
- 被举报或被撤销的地点信息比例

## 九、当前最大风险

1. 现有竞品功能覆盖广，当前差异化可能仍不够强。
2. 高价值野钓标点天然不愿公开，公开数据可能只剩低质量内容。
3. 天气和鱼情容易被用户理解成结果承诺。
4. 第一版功能仍然偏多，个人或小团队开发周期可能失控。
5. 地点真实性、禁钓规则和安全状态需要持续运营，不能只靠技术。
6. 分享战报是否能带来有效用户尚未验证。
7. 地图和定位数据涉及隐私、地图服务许可及内容审核成本。

## 十、希望 Claude 重点挑战的提案

请不要默认接受本提案。尤其需要给出：

- 一个比当前定位更尖锐的替代定位
- 最应该从 P0 删除的 3 项功能
- 一个即使没有社区数据也成立的 MVP
- 一个解决用户不愿公开精准标点的更强机制
- 一个 30 天内能验证需求真假的实验方案
